# Project Spec — 2026-10-16

## 场景

车机本地 QQ 音乐、网易云音乐等继续负责真正的音频播放；CarLife 只用于导航。PSA Lyric 读取系统当前活跃播放器状态，自行匹配歌词并覆盖在车机界面上。

参考屏幕为 1920×720。上传截图中：
- 左侧系统导航栏约 x=0..112。
- CarLife 主区域约 x=113..1361。
- 右侧卡片列约 x=1373..1908。
- 顶部车辆卡片约 x=1373..1908, y=10..238。
- 右下音乐/歌词卡片约 x=1373..1908, y=249..719。
因此初始悬浮歌词区域应以 **x≈1373, y≈249, w≈535, h≈471** 为 1920×720 的参考基准，并提供位置/尺寸微调与保存。

## 媒体链路

1. NotificationListenerService 获得 MediaSessionManager.getActiveSessions() 访问资格。
2. 从活跃会话选择正在播放、且标题/歌手信息有效的播放器。
3. 订阅 PlaybackState + MediaMetadata；用 position + lastPositionUpdateTime + speed 进行播放位置插值。
4. TransportControls 实现上一首 / 播放暂停 / 下一首；可选 seekTo()。
5. 会话短暂消失时设置防抖窗口，避免歌词闪空。

## 歌词链路

- 当前播放器元数据作为歌曲身份入口。
- 目标支持逐行 LRC、逐字时间轴、翻译/罗马音和本地 sidecar 歌词。
- 在线歌词采用 provider 接口隔离；搜索、候选打分、歌词正文、缓存彼此解耦。
- 需要“当前歌曲校准”和全局偏移，正值=歌词提前。
- 若逐字歌词不可用，不伪造逐字时间；退化为逐行切换。

## Apple 风格歌词视觉基线

根据上传 md3Music 视频、截图和源代码行为审查，需独立实现：
- 当前行固定在视口偏中上位置；默认锚点约 0.35。
- 行切换使用弹簧滚动，不做线性硬切。
- 当前行 scale=1；非当前行默认约 0.85，并在进/退场时平滑缩放。
- 非当前行按离当前行距离分级高斯模糊；用户手动滚动时模糊淡出，自动回弹时恢复。
- 当前逐字进度带渐变/填充；已唱过字符有轻微上浮。
- 辉光可开关并按歌词字长/节奏阈值触发。
- 动态歌词色由封面主色与白色混合。
- 对唱优化：男女/合唱前缀识别后左右/居中布局。
- 平衡换行：长行尽量均衡拆分，而非简单超过宽度立即换行。
- 上下边缘渐隐。
- 用户拖动歌词后保留浏览位置，超时自动弹回当前行。
- 字号、字重、行间距、字体、模糊、辉光、动态颜色、对唱、平衡换行均可调。

上传设置基准：字号 29px、字重约 600（半粗）、行间距 0.9×；该组值作为“车机预设”的候选默认值，待确认。

## 悬浮窗行为

- WindowManager TYPE_APPLICATION_OVERLAY。
- 默认右下 535×471 参考区域；支持拖动、调整尺寸和复位。
- 锁定后可切换 FLAG_NOT_TOUCHABLE，使点击穿透给 CarLife。
- 正常交互模式支持歌词拖动、控制按钮、位置调整。
- 前台应用规则用于在车机 Launcher / CarLife / 音乐播放器间切换显示形态。
- 需要兼容 Android 9。

## 背景

模式 A：专辑封面高斯模糊。可直接实现、性能和权限成本低。

模式 B：当前屏幕内容高斯模糊。Android 9 普通 overlay 无法直接读取“下面其他 App 的像素”；真实实现需要 MediaProjection 截屏/录屏授权，或车机系统特权接口。若采用 MediaProjection，建议低频快照 + GPU/RenderScript 模糊，而非 60fps 连续捕获，以控制功耗。

## CI / 交付

- GitHub Actions：JDK 17 + Gradle，执行 unit tests、lint、assembleRelease。
- 目标为可侧载 Android APK，不依赖 Play。
- 项目所有者负责最终签名、安装，以及把 ADB 测试交给 Codex。
- CI 保留 SHA-256、versionName/versionCode、commit SHA 与构建日志，便于网页会话/Codex 交接。
